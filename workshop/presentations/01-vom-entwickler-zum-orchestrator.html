LSP vs. Agent Understanding

Warum eure IDE plötzlich ein Hilfsmittel und nicht das Cockpit ist

📍 IDE / Language Server Protocol

„Zeigt mir Informationen über Code.“

  • Hover, Goto-Definition, Find-Refs
  • Syntax-Check, Auto-Completion
  • Statisch, file-by-file

🧠 Coding Agent

„Versteht und erklärt mir den Code.“

  • Cross-File-Reasoning
  • Domain-Begriffe lernen via ai_docs/
  • Refactoring von historisch gewachsenem Code
  • Erklärt das „Warum“, nicht nur das „Was“

→ Egal ob C++/C#-Schnittstellen, WPF-Window-Hierarchie, Codesys-FB-Bibliothek oder SPS-Programmlogik. Cross-File-Reasoning ist die universelle Stärke.

Konversation statt Auto-Completion

Tab-Tab-Tab

Reaktiv. KI schlägt das nächste Wort vor.

„Aber meine IDE hat keine KI“

Für die SPS/Motion-Programmierer im Raum — und alle, die mal in einem ähnlichen Setup landen

🎯 Der Trick

Der Coding-Agent läuft in einer Sandbox-Umgebung, NICHT in eurer IDE.

Solange euer Tool über Dateien, APIs oder Konfiguration steuerbar ist, kann der Agent damit arbeiten.

🔓 Was geht heute schon

  • TIA Portal: Openness API, DLL-basiert, C# darüber → Agent nutzbar
  • Codesys: Export/Import, ST-Code als Text → Agent kann lesen, schreiben, prüfen
  • VBA / Macros: Reine Textdateien, perfekt für Agents
  • Codierichtlinien-Check: Agent liest Code, vergleicht mit Doku, gibt Bericht
  • Test-Generierung: auch ohne IDE-KI möglich, wenn Tests als Text definiert sind

Wenn die KI deine Software über Dateien, APIs oder Konfiguration beeinflussen kann — kann sie damit arbeiten. Das gilt für SPS, Motion, C#, C++, Office-AddIns gleichermaßen.

Was heute NICHT passiert

Erwartungs-Management, damit ihr nicht am Ende enttäuscht seid

  • Multi-Agent-Orchestrierung (Stufe 3) — das ist Folge-Workshop-Stoff
  • Autonome Agents über Nacht — brauchen anderes Vertrauens-Niveau
  • Background-Agents in eurer IDE — nicht in Stufe 2
  • Tool-Vergleiche (Cursor vs. OpenCode vs. Copilot) — wir nutzen OpenCode, weil es zu eurem LLM-Routing passt
  • Auto-Commit durch den Agent — ist Compliance-Policy (interne Risikobeurteilung), Mensch macht den Commit
  • Eine fertige Antwort auf „welcher Vendor langfristig“ — das löst der Markt, nicht 1,5 Tage Workshop

Was heute SCHON passiert

Ihr werdet bis Ende Tag 2 in der Lage sein, mit einem Coding-Agenten reproduzierbar zu arbeiten. Eine Pipeline gebaut zu haben. Und sagen können: „Ich habe nicht selbst getippt, der Agent hat — und der Code ist gut.“

Wie das aussehen kann (Stufe 3–4)

Kurzer Blick in mein eigenes Setup — nicht zum Nachbauen, nur als Horizont

🎼 Bead-Orchestrator

17 Phasen pro Aufgabe — Sizing → Plan → Implementer → Review → Codex-Adversarial → Verification (VETO) → UAT → Constraints → Changelog → Close.

Eine ausgewachsene Variante eurer Stufe-2-Pipeline.

🌊 Wave-Orchestrator

Mehrere Aufgaben parallel über cmux-Panes. Dependency-aware Wellen. Long-lived Monitor parkt auf Status.

3–5 Agenten gleichzeitig, ich gucke nur drauf.

🔍 Independent-Reviewer

Ein Agent schreibt, ein zweiter (mit anderem Kontext) reviewt, ein dritter verifiziert. Adversarial Pattern.

KI checkt KI — reduziert Halluzinations-Risiko.

Das ist mein Tagesgeschäft. Es braucht 2–3 Monate, da hinzukommen — und Stufe 2 als sicheres Fundament. Wer Stufe 2 nicht beherrscht, kann Stufe 3 nicht aufbauen.

Kurze Live-Demo, falls die Sandbox mitspielt — sonst zeig ich’s euch in der Pause.
